
## Context

We are building a classification evaluation and analysis system. The system classifies items into a hierarchical taxonomy using both static mapping and an LLM.

## Classification Logic

The classification pipeline maps input data into a hierarchy:

* **Input**: JSON containing:

  * `attributes` (JSON)
  * `metadata` (JSON)

* **Output classification**:

  * `type` — high-level category (e.g., books, cars, movies)
  * `subtype` — category within a type
    Examples:

    * Books → fiction, guides
    * Cars → sport, compact
    * Movies → romantic, comedy

* **Type classification**: Determined using a static dictionary mapping.

* **Subtype classification**: Determined using an LLM call.

## Model Evaluation

To evaluate the model, we use a **benchmark dataset** containing items with ground truth subtype labels.

For each model version:

1. The benchmark dataset is run through the classification pipeline.
2. Predicted subtype is generated.
3. Results are stored in a PostgreSQL database.

## Database Schema

### 1. Run Results Table

Table name: `timestamp_run_id_results`

Columns:

* `request_id`
* `attributes` (JSON)
* `metadata` (JSON)
* `true_type`
* `pred_type`
* `true_subtype`
* `pred_subtype`

### 2. Leaderboard Table

Columns:

* `benchmark_id`
* `benchmark_length`
* `subtype_accuracy`
* `subtype_weighted_f1`
* `type_weighted_f1`

## System Requirements

The system should provide a UI/dashboard that allows users to analyze classification performance.

### Feature 1 — Leaderboard View

* Display leaderboard results per benchmark.
* Include a dropdown to select benchmark.
* Display metrics:

  * Subtype accuracy
  * Subtype weighted F1
  * Type weighted F1

### Feature 2 — Prediction Filtering

User can choose to display:

* All predictions
* Only incorrect subtype predictions

### Feature 3 — Specific Run Analysis

For a selected run:

1. Display **type confusion matrix**.
2. When clicking a cell in the type confusion matrix:

   * Display the **subtype confusion matrix** for the relevant type pair.
3. When clicking a cell in the subtype confusion matrix:

   * Display the relevant items in a row-level data table.

**Row-level table columns**:

* `request_id`
* `attributes` (JSON)
* `metadata` (JSON)
* `true_type`
* `pred_type`
* `true_subtype`
* `pred_subtype`

### Feature 4 — Run Comparison (Drift Detection)

Compare two runs from the same benchmark.

Display a **transition matrix**:

* Shows how predictions changed from subtype A → subtype B between runs.
* Matrix is **not symmetric**.
* Only show transitions where prediction changed.

Filtering:

* User can filter transitions by minimum number of changed records (slider range 1–50).

Clicking a transition cell should display the relevant row-level records.
